# VUI Theme Studio

The theme engine extends the existing `vui/theme` API and the existing component tokens. No portal code, preview template or editor is shipped in the reusable library. The original seven `light`, `dark`, `system`, `high-contrast` and neon themes keep their public API and CSS entry points.

## Architecture and files

- `src/theme/palettes.ts`: upstream base colors, independent of components.
- `src/theme/presets.ts`: nineteen immutable presets and the allowlisted semantic color tokens, with derived hover, border and contrast values.
- `src/theme/colors.ts`: strict portable HEX/RGB/HSL normalization and contrast utilities.
- `src/theme/engine.ts`: application, registration, validation, persistence, history, JSON and CSS exports.
- `src/theme/install.ts`: installs all preset selectors once; component styles are shared across themes.
- `src/showcase/theme-studio.ts`: documentation-only editor using public APIs and actual `vui-*` elements.
- `src/showcase/theme-preview.ts`: live components plus dashboard, settings, login and developer-tool reference compositions.
- `src/showcase/documentation.ts`: documentation preferences, search and copy actions.

Semantic tokens map to existing properties, for example `foreground` → `--vui-color-text` and `primaryForeground` → `--vui-color-on-primary`. New card, modal, popover, secondary, accent, interactive text and disabled tokens extend the existing vocabulary; components fall back to the original tokens for older integrations. Shadow is an editable color, while the engine generates `--vui-shadow-sm/md/lg` from the same geometry as the `ui.css` recipes (override only when shadow intensity is set). No unvalidated CSS expressions are accepted in imports.

## Defaults and persistence

```ts
import { initializeTheme, applyTheme, saveThemePreference } from "vui/theme";
const stopFollowingSystem = initializeTheme();
// No preference: Catppuccin Mocha for dark systems, Catppuccin Latte for light systems.
saveThemePreference("nord");
applyTheme("nord");
```

`initializeTheme` follows later system changes only while no explicit preference exists. Preferences are stored under `vui.theme.preference.v1`, custom themes under `vui.theme.custom.v1`. Storage is local to the browser and origin. The docs use a validated synchronous head bootstrap generated by Vite to apply the initial canvas before first paint. Consumers with SSR should set initial tokens in their own head using the same palette configuration; a restrictive CSP requires a nonce/hash for that bootstrap.

`applyTheme(theme, element)` scopes the theme to one element and its descendants, including shadow-DOM components. Theme Studio edits only its preview roots. **Apply to documentation** is the explicit action that changes and persists the documentation interface. Documentation preferences and draft history never share mutable objects.

## Using Theme Studio

1. Open `/#theme-studio` (`?lang=en#theme-studio` for English).
2. Select a preset; the five swatches preview its main colors.
3. Search tokens by English identifier or translated label. Pick a color or enter HEX, RGB or HSL, including alpha. Invalid input is marked and never applied.
4. Try the components or switch preview templates. Existing controls retain state while changing colors. Mobile **Customize / Preview** tabs preserve the draft.
5. Use individual reset buttons, **Undo / Redo**, or **Restore preset**. **Compare original** displays the immutable base alongside the draft. Contrast warnings name the affected pairs and ratios; they do not silently overwrite your choices.
6. Set a unique name and **Save new**. Select a saved theme, rename it or delete it. To create a variation, use a new name and save again. Up to 50 local themes are supported. If storage is blocked, editing and exports still work and the page reports the issue.
7. **Copy CSS**, **Download CSS**, **Download JSON** and **Import JSON** use schema version 1. Imports are limited to 64 KiB, allowlisted tokens, finite bounded appearance values and normalized color literals. JSON is data, never executable code.

Global radius, independent Boxes/Fields/Selectors radii, border width, shadow strength and UI mode (`web` | `desktop`) are optional appearance overrides. All radius values are pixels in the range 0–32; border width is 0–4 px. The existing secondary variant remains available, alongside semantic tones and solid/soft/outline/ghost variants. `vui-panel` is the actual card primitive; `vui-data-grid` is the actual table primitive. Authentication and dashboard previews are local demonstrations, not backend services.

## Import and export

```ts
import {
  importThemeJSON,
  applyTheme,
  exportThemeCSS,
  registerTheme,
} from "vui/theme";
const draft = importThemeJSON(jsonText);
applyTheme(draft, document.querySelector<HTMLElement>("#my-app")!);
registerTheme("my-brand", draft);
applyTheme("my-brand");
const css = exportThemeCSS(draft);
```

CSS export contains a `[data-vui-theme="custom"]` selector with semantic colors and optional appearance deltas only. Import it **after** VUI's standard token CSS and set `data-vui-theme="custom"` on your app root. Structural scales live on `[data-vui-ui]` (`web` | `desktop` | `terminal`) from `vui/themes/ui` — they are not duplicated in the export. Set `data-vui-ui` when using an appearance UI mode override; the JS API does this automatically. Scope a custom selector further if the application contains several independent theme roots.

JSON stores `schemaVersion`, `name`, `baseTheme`, `mode`, only changed `tokens`, and optional `appearance`. Presets remain frozen and are never modified by imported data. Unknown versions, unknown fields, unknown tokens, CSS URLs and arbitrary CSS expressions are rejected. Keep JSON as the source of truth for later editing; CSS is the runtime artifact.

## Adding a built-in theme

Add its named base palette to `palettes.ts` and its identifier, name and mode to `definitions` in `presets.ts`. The existing derivation produces the complete semantic token set, picker entry and static CSS selectors automatically. Add the upstream reference below, then run typecheck, tests and builds. If the palette has unusual surface luminance, extend the AA pair tests rather than copying component CSS. Applications can instead use `registerTheme` without modifying the package.

## Palette sources

Base palettes were checked against these upstream sources. Semantic surfaces and muted/status/border colors are derived or adjusted for WCAG AA while preserving their recognizable palette.

- [Tokyo Night](https://github.com/folke/tokyonight.nvim/tree/main/lua/tokyonight/colors): night/storm; Day uses the light palette convention derived by the upstream inversion.
- [Catppuccin](https://github.com/catppuccin/palette/blob/main/palette.json): Mocha and Latte.
- [Dracula](https://github.com/dracula/vim/blob/master/autoload/dracula.vim).
- [Nord](https://github.com/nordtheme/nord/blob/develop/src/nord.css).
- [Rosé Pine](https://github.com/rose-pine/neovim/blob/main/lua/rose-pine/palette.lua): main and dawn.
- [Kanagawa](https://github.com/rebelot/kanagawa.nvim/blob/master/lua/kanagawa/colors.lua): Wave.
- [SynthWave](https://github.com/robb0wen/synthwave-vscode/blob/master/themes/synthwave-color-theme.json): SynthWave '84, without expensive glow effects.
- Desktop Light / Desktop Dark (legacy theme ids `fluent-light` / `fluent-dark`): color adaptations that also set `appearance.uiMode` to `desktop` (structure from `ui.css`). See THIRD_PARTY_NOTICES.md for source attribution.
- [Radix Colors](https://www.radix-ui.com/colors/docs/palette-composition/scales): Radix Light and Radix Dark (slate + indigo/purple) adaptations; selecting them keeps soft radii as appearance deltas without forcing a UI mode.
- Terminal UI mode is structural only (monospace, dense, square, no elevation). Any color theme can pair with `data-vui-ui="terminal"`.

The `interactiveText` token separates readable link/tab text from the specified solid primary button color. Text and muted colors are checked against the canvas, all surfaces, selection and state surfaces. Custom colors can violate contrast. The editor reports normal-text contrast below 4.5:1; disabled text is deliberately exempt. Preset tests enforce normal-text pairs and primary button hover/active states for contrast-adjusted presets. Retro preserves its supplied source colors, including low-contrast solid/content pairs, and reports these in the editor. All eight semantic tones, including secondary and an independent neutral color, support solid, soft, outline and ghost variants. Alpha foregrounds are composited against the checked background. Translucent backgrounds are evaluated over white; verify consumer-specific underlays separately.

### Shape, strokes and hover

`appearance.radiusBox`, `radiusField` and `radiusSelector` map to
`--vui-radius-box`, `--vui-radius-field` and `--vui-radius-selector`. Boxes cover
cards/panels, tables, dialogs, menus and feedback containers. Fields cover
buttons, inputs, selects and tabs. Selectors cover checkboxes, switches, toggles,
badges and chips. Radios, avatars and spinners retain their circular geometry.
The old `appearance.radius` remains a global fallback; explicit family overrides
win. Missing JSON properties inherit the preset defaults. Retro uses 8/4/4 px,
a 1 px border and zero shadow strength, matching the supplied generator settings.

`blockBorder` is the editable decorative stroke used by cards and structural
containers. It derives from card/background text at a low tint. `controlBorder`
keeps field boundaries readable; tone borders and `focusRing` remain separate.
All ordinary strokes use `appearance.borderWidth`; focus outlines stay visible
even at border width zero. Legacy CSS entry points fall back to the old tokens.

Interactive rows, navigation, fields and buttons share soft color transitions.
Semantic soft/outline/ghost actions use a tint on hover instead of inset shadows.
Generated hover colors retain readable text for contrast-adjusted presets.
The **Tabs** preview includes live panels, keyboard navigation and a disabled tab.
Tabs use content widths, family radii and decorative borders with no box shadow.
